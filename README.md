# Dear Us

> 과거의 나, 그리고 그때의 우리와 다시 대화하는 AI 회고 일기

수업(실감디지털콘텐츠기획) 팀 프로젝트로 만드는 모바일 앱(iOS · Android)이에요. 앱 코드는 `app/`, 서버 코드는 `server/`에 있어요.

**지금 상태 (2026-10-29 기준):** 일정상 10월 4주 차예요. 백엔드는 로그인 · 일기 · 메신저 업로드 · 페르소나 시점 고르기 · 대화 세션 만들기까지 동작하고, AI 답변 채팅을 만드는 중이에요. 프론트엔드는 `app/`이 아직 레포에 올라오지 않았어요. 자세한 표는 [4. 어디까지 했나요](#4-어디까지-했나요)에 있어요.

---

## 1. 무엇을 만드나요

일기와 메신저 대화를 바탕으로 **특정 시점의 나를 AI 페르소나로 다시 만들어서 대화**하는 앱이에요. 커플은 같은 날에 대한 서로의 기억을 나란히 비교할 수 있어요.

```
① 기록         ② 분석 · 축적        ③ 과거의 나 만들기      ④ 대화 · 회고
일기 쓰기   →   말투 · 감정 · 상황  →  고른 시점의 기록으로  →  과거의 나와 대화
(또는 카톡         분석해서 저장         AI 페르소나 구성        현재와 비교, 리포트
 캡처 업로드)
```

| 기능 | 내용 |
|---|---|
| 일기 · 캘린더 | 일기와 감정 태그를 쓰고, 캘린더에서 날짜별로 다시 봐요. |
| 메신저 업로드 | 일기 쓰기 귀찮은 날은 카카오톡 대화 캡처를 올려요. 글자 읽기와 민감정보 가리기는 폰 안에서 하고, 가린 글자만 서버로 보내요. |
| 과거의 나와 대화 | 바로가기(1개월 · 6개월 · 1년 전)는 그 무렵 전후 2주, 캘린더에서 고른 날은 그날 하루의 기록으로 페르소나를 만들어요. 최대 1년 전까지 고를 수 있어요. |
| 리포트 | 대화가 끝나면 당시 고민과 지금의 변화를 한 줄로 정리해요. |
| 커플 모드 | 초대 코드로 연결하고 두 사람이 모두 동의하면, 같은 날 각자 자기 과거의 나와 나눈 대화의 요약을 나란히 보여줘요. |

### 꼭 지키는 약속

- **사진은 폰 밖으로 나가지 않아요.** 서버에는 사진을 받는 API가 없어요(이미지를 보내면 415).
- 서버는 받은 글자를 규칙으로 한 번 더 가린 뒤에만 AI로 보내고, 요약이 끝나면 받은 글자를 지워요. 일기도 가린 뒤에만 AI로 보내요.
- AI를 부르는 기능은 AI 분석 동의가 있을 때만 쓸 수 있어요. 동의를 철회하면 저장된 분석 데이터를 바로 지워요.
- AI 모델은 Claude Haiku 5.5예요. 앱이 AI나 DB를 직접 부르지 않고, 항상 Spring Boot 서버만 불러요.

## 2. 어떻게 만들어요

### 구조와 기술

```
앱 (Expo · React Native) ──→ 서버 (Spring Boot) ──→ Supabase (PostgreSQL)
  폰 안에서 글자 읽기 · 가리기          └──→ Anthropic API (Claude Haiku 5.5)
```

| 구분 | 기술 |
|---|---|
| 앱 | Expo SDK 57 · React Native 0.86 · TypeScript · Expo Router · TanStack Query v5 |
| 글자 읽기 (폰 안) | Android Google ML Kit · iOS Apple Vision. 개발 빌드(EAS)가 필요해요 |
| 서버 | Java 21 · Spring Boot 4.1 · Gradle · Flyway |
| DB | Supabase (PostgreSQL). DB 용도로만 쓰고 인증 · 로직은 서버가 맡아요 |
| AI | Anthropic Claude Haiku 5.5. 서버에서만 호출해요 |
| 배포 | Render (서버) · Expo EAS Build (앱) |

버전과 선택 이유는 [DearUs_기술스택.md](DearUs_기술스택.md)에 있어요.

### 역할과 작업 방식

팀원 두 명이 한 쪽씩 맡아요.

| 담당 | 폴더 | 하는 일 |
|---|---|---|
| 백엔드 | `server/` | API, DB, 로그인, AI 연동(요약 · 페르소나 · 채팅 · 리포트), 서버 쪽 민감정보 가림 |
| 프론트엔드 | `app/` | 화면, 폰 안 글자 읽기 · 가리기 · 검수, 소셜 로그인 연결, API 연동 |

- **둘의 약속은 [server/openapi.yaml](server/openapi.yaml)이에요.** 요청 · 응답을 바꿔야 하면 명세부터 고치고 둘이 합의해요.
- **프론트엔드는 서버를 기다리지 않아요.** 명세대로 만든 가짜 데이터로 먼저 개발하고, 화면은 API 호출 함수만 불러서 나중에 실제 호출로 쉽게 바꿔요.
- **백엔드는 프론트엔드가 막히지 않게 도와줘요.** AI 키 없이 `AI_PROVIDER=fake`로 가짜 요약을 쓰고, 가짜 로그인(`POST /auth/dev`)을 열어 둬요.
- 지금 바로 실제 서버에 붙일 수 있는 API는 로그인(dev) · 동의 · 일기 · 메신저 업로드 · 페르소나 시점 고르기 · 대화 세션 만들기와 목록이에요.
- UI는 [DearUs_스토리보드.html](DearUs_스토리보드.html)(화면 20장)이 기준이고, 화면마다 필요한 API와 테이블이 적혀 있어요.

## 5. 실행해 보기

### 서버

```bash
cp server/.env.example server/.env
```

`server/.env`를 채워요. DB 접속 값과 암호화 키(`ENCRYPTION_KEY`)는 백엔드 담당에게 받아요. 같은 DB를 쓰는 사람은 `ENCRYPTION_KEY`가 모두 같아야 서로 저장한 요약을 읽어요. AI 키 없이 해보려면 `AI_PROVIDER=fake`로, 가짜 로그인을 쓰려면 `DEV_LOGIN_ENABLED=true`로 둬요.

```bash
cd server
./gradlew bootRun
```

단위 테스트는 DB 없이 `./gradlew test`로 돌려요.

### 앱

앱은 `app/`이 올라온 뒤 `npx expo start`로 켜고, 실제 폰에서 Expo Go로 확인해요. 글자 읽기와 소셜 로그인은 Expo Go에서 안 돼서 개발 빌드(EAS)를 써요.
