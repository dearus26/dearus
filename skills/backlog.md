# 나중에 따로 처리해야 할 사항

> 일부러 미뤄 둔 것, 아직 만들지 않은 것, 정해야 하는 것, 코드에서 일부러 단순하게 둔 것을 한곳에 모았어요. 마지막 정리: 2026.11.11 (개인정보처리방침 결정과 그에 따른 할 일 반영. 그 앞은 2026.11.9 txt 원문 저장 · V7 · 페르소나에 원문 더하기를 반영하고 진짜 Claude로 서버 흐름을 끝까지 시험한 결과 반영. 이어서 서버의 이미지 올리기 API · 이미지 읽기, 일기 · 대화 · 리포트의 가림 제거, 1년 만료 삭제 작업 반영. 그 앞은 2026.11.8 메신저 업로드를 이미지 · txt 방식으로 바꾸고 글자 가림을 없앤 결정과, 원문 저장 · 이미지 API · 철회 규칙 · 스토리보드 수정 등 남은 결정 반영. 그 앞은 2026.11.4 소셜 로그인 서버 구현 · 앱 호출 확인 직후).
> 처리하면 상태를 ✅로 바꾸고 날짜를 적어요. 새로 미루는 일이 생기면 여기에 먼저 적어요.
> 상태: ⏳ 아직 / 🔧 일부 함 / ❓ 정해야 함 / ✅ 끝남

## 8. 코드에서 일부러 단순하게 둔 것 (알려진 한계)

| 항목 | 지금 방식 | 문제가 될 때 |

| 전후 2주에 쓰는 메신저 주는 겹치는 주 전체 | 구간 끝 뒤 최대 6일의 요약이 섞일 수 있어요 | "그 뒤의 일은 모른다"가 엄격해야 한다면 |
| 같은 주를 여러 번 올리면 최신 요약만 사용 | 서로 다른 txt를 합치지 않아요 | 한 주를 나눠서 올리는 사용자가 많다면 |
| 글자를 가리지 않고 원문을 1년 보관 | 개인정보와 상대방 정보가 AI와 서버로 가요. txt는 상대 말을 폰에서 버리고 내 말만 보내요. 이미지는 상대 말과 이름이 찍힌 사진이 서버와 AI로 가므로 읽은 직후 삭제해요(2026.11.8 결정) | 동의 화면과 약관에 AI 전송과 보관 기간을 분명히 안내하고, 철회하면 30일 뒤, 탈퇴하면 바로 원문을 지워요(2026.11.8 확정, 5장) |
| 대화 이력은 최근 20턴만 보냄 | 더 오래된 말은 AI가 몰라요(요약해서 붙이지 않아요). 긴 대화에서 초반 맥락을 잃을 수 있어요 | 긴 대화를 많이 한다면 오래된 이력을 요약해서 붙이기 |
| 답변은 끝나야 저장 | 서버가 답변 도중에 꺼지면 그 턴은 사라져요(앱이 같은 글을 다시 보내요) | 그런 일이 잦다면 |
| 동시 답변 16개 · 대기 32개 | 넘치면 503 `SERVER_BUSY` | 사용자가 많아지면 풀 크기와 비용 상한을 함께 |
| 분석에 실패한 세션은 새로 만들어 다시 시도 | 실패한 세션이 목록에 남아요 | 실패 세션이 쌓여서 목록이 지저분하면 정리 규칙 |
| 끝내기 · 리포트 잠금도 서버 한 대 가정 | 끝내는 동안 같은 세션을 막는 잠금(`ChatReplyService.tryLock`)이 서버 메모리예요. 서버가 여러 대면 `reports.session_id`의 유일 키가 중복 리포트를 막고, 늦게 온 쪽은 먼저 만든 결과를 돌려줘요 | 서버를 여러 대로 늘릴 때 |
| 끝내지 않은 대화는 계속 열려 있음 | 서버가 자동으로 끝내지 않아요(2026.11.4 결정). 끝내지 않은 대화는 리포트가 없고 목록에서 이어서 대화할 수 있어요. 동의를 철회하면 끝내기도 403이라 열린 채로 30일 뒤 지워져요 | 리포트를 안 만들고 떠나는 사용자가 많다면 N시간 뒤 자동 종료를 검토 |
| 대화 시간의 계산 | 메시지 사이 간격을 5분까지만 더해서, 며칠 뒤 이어서 말하면 그 첫 말마다 최대 5분이 잡혀요. 첫 인사부터 첫 말까지도 최대 5분이에요 | 숫자가 부풀려 보인다면 상한을 줄이거나 오래 쉰 간격은 0으로 |
| 대화 목록 최대 50개 | 더 오래된 대화는 목록에 안 보여요 | 대화가 많은 사용자 |
| 소셜 로그인 호출 제한 없음 | 로그인 요청마다 카카오 API를 2번 부르고 구글은 공개키를 캐시해 써요. 횟수 제한이 없어서 같은 IP에서 반복 요청하면 카카오 호출 한도를 쓸 수 있어요 | 일반 API의 요청 횟수 제한(1장 비용 · 남용 방어)과 함께 |
| 토큰 인증 | 갱신 토큰 없이 14일 JWT. 만료되면 다시 로그인 | 14일마다 로그인하는 게 불편하다면 |
| 스크린샷은 메모리에서만 다룸 | 한 업로드의 사진(최대 50MB)을 읽기가 끝날 때까지 메모리에 들고 있어요(디스크 · DB에 쓰지 않으려고요). 메신저 작업 줄은 동시에 2건이고 기다리는 줄의 길이에는 제한이 없어요 | 여러 사람이 동시에 큰 업로드를 하면 메모리가 모자랄 수 있어요(Render 무료 서버 512MB). 기다리는 줄에 상한을 두거나 한도를 줄이기 |
| 스크린샷이 60주를 넘으면 | txt는 400이지만 이미지는 202 뒤에 알게 되어서, 가장 최근 60주만 요약하고 나머지는 버려요 | 오래된 대화를 한꺼번에 올리는 사용자가 많다면 |
| 스크린샷 묶음 사이의 겹침 | AI에는 10장씩 나눠 보내서, 앞 묶음의 끝과 다음 묶음의 앞이 같은 항목이면(겹친 내 말이 10자 이상) 한 번만 남겨요. 짧은 말 하나가 우연히 같으면 그대로 둬요. 한 묶음 안의 겹침은 AI가 한 번만 적어요 | 이미지 읽기 시험에서 겹침을 놓치거나 지나치게 지우는 일이 보이면 |
| 첫 날짜 구분선보다 앞의 말 | 스크린샷에서 날짜를 알 수 없어서 빼요. 오늘보다 뒤의 날짜(잘못 읽은 날짜)에 붙은 말도 빼요 | 빠지는 말이 많다면(앱이 "날짜 줄이 보이게 캡처해 주세요"를 안내해요) |

## 이 문서를 관리하는 법

- 새로 미룬 일은 바로 위 표 중 알맞은 곳에 추가해요.
- 끝낸 일은 ✅와 날짜를 적고, 한 달쯤 지나면 지워도 돼요.
- 결정이 나면 `AGENTS.md`의 "확정된 결정"과 관련 문서에 반영하고, 여기서는 상태만 ✅로 바꿔요.
- 이 파일은 팀이 같이 봐서 `.gitignore`에 예외를 두었어요(다른 md는 `README.md`만 올라가요). 고치면 일반 파일처럼 커밋해요.
- 프롬프트 문구는 `ChatPromptBuilder`(대화) · `PersonaAnalyzer`(시점 분석) · `WeeklySummarizer`(메신저 요약)에 있어요.
