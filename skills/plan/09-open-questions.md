## 9. 추가 검토 사항

| 항목 | 내용 |
|---|---|
| 서비스명 통일 | 발표 · 문서 표기는 'Dear Us', 코드 식별자(패키지명 · 저장소 · 환경변수 등)는 `dearus`로 확정. 슬라이드 등 기존 자료에 남은 'Dear, Me' 표기를 'Dear Us'로 수정 필요 |
| 요약 생성과 원문 보관 | 이미지로 올린 사진은 AI가 내 말을 읽은 직후 삭제함. 서버가 받은(또는 읽어낸) 내 말 원문은 1년 보관하고, 요약은 "요약 생성 → 암호화 저장" 순서로 처리한다고 명시. 만료된 원문은 매일 새벽 도는 삭제 작업(`MessengerExpiryJob`, 2026.11.9)으로 지움 |
| 재현도와 프라이버시의 균형 | 요약 기반 페르소나로 세부 목표 5(3.5점 이상) 달성이 가능한지 사전 테스트 |
| 커플 모드 목표 수치 | 세부 목표 6의 접근 차단 시간 등 구체 수치 확정 |
| 커플 리포트 확장 | 현실 대화를 이끌기 위해 "연인에게 물어보면 좋을 질문"을 리포트에 추가할지 검토 |
| 유사 앱 검증 | 'Lexikon · Rosebud · 비트윈' 등 "확인 필요" 항목은 직접 사용 후 보완 |
| 일기 앱 리뷰 | 하루콩 · Day One의 1~2점 리뷰를 직접 수집해 3.6절 보완 |
| AI 모델 | Claude Haiku 5.5로 확정(2026.10.28). 한국어 말투 재현 · 첫 응답 시간은 8.5의 블라인드 시험으로 확인하고, 모자라면 대안(Gemini 3.5 Flash-Lite 등)으로 바꿔요. 네이버 CLOVA Studio는 요금 · 약관을 확인하지 못해 비교에서 빠졌어요 |
| 동의 화면의 AI 보관 안내 | 입력 · 출력이 Anthropic 서버에서 30일 안에 삭제될 때까지 남고(정책 위반으로 걸리면 최대 2년) 한국 밖에서 처리될 수 있다는 문장을 약관 · 동의 화면에 넣어요. 동의 철회 뒤 우리 서버도 30일 보관한 뒤 지우므로 "철회하면 약 30일 뒤 모두 지워져요"로 한 번에 안내할 수 있어요. 개인정보 국외 이전 규정 확인 필요(법률 검토) |
| 동의 철회와 보관 | 2026.10.29 결정: 철회하면 AI 사용은 즉시 막고, 분석(메신저 원문 · 요약 · 시점 분석)과 대화 기록은 30일 보관한 뒤 파기. 그 안에 다시 동의하면 이어서 사용. 일기는 지우지 않음. 철회 화면과 동의 화면에 "○월 ○일에 모두 지워져요" 안내가 필요해요(`GET /me`의 `aiDataDeleteAt`) |
| AI 거절 · 비용 방어 | 2026.11.2 결정: 둘 다 나중에. 거절(`refusal`)은 지금 서버 오류로만 알리고(실제 호출에서 한 번도 안 났어요), 하루 호출 상한 같은 비용 방어는 없어요(한 턴 약 0.05센트). 베타 전에 정해요. 목록은 `skills/backlog.md` |
| 소셜 로그인 계정 연결 | 2026.11.4 결정: 제공자마다 별개 계정(이메일 불수집). 이메일이 같으면 합치는 방식은 카카오 비즈 앱 전환과 이메일 동의항목, `user_identities` 테이블, 개인정보 문서 수정이 필요해서 하지 않았어요. 필요해지면 다시 검토 |
| 애플 로그인 | 서버 검증은 아직 없어요(501). 애플 개발자 계정이 필요할 수 있어요(확인 못함). 수업 시연만 한다면 뺄지 팀이 정해요 |
| 일기 · 메신저 AI 전송 동의 문구 | 약관 · 동의 화면의 '일기 · 대화 내용 AI 분석'(스토리보드의 "(Gemini)" 표기는 Claude Haiku 5.5로 정하면서 뺐어요. 회사 이름을 화면에 적을지는 팀이 정해요)을 쓰는데, 스토리보드의 '가린 내용만 AI로 보내고 학습에는 쓰이지 않아요' 문구는 글자를 가리지 않게 되어 고쳐야 해요. 새 문구에는 AI 전송 범위(이미지는 상대 말과 이름이 찍힌 스크린샷 전체, 사진은 읽은 직후 삭제), 내 말 원문 1년 보관, 학습에 쓰이지 않는다는 점, AI 회사의 30일 보관을 담아요. 세부 약관 내용(각 항목의 >)은 작성 필요 |
| 카카오톡 txt 형식 | 내보내기 파일의 형식이 기기 · 버전마다 다를 수 있음. 안드로이드 · 아이폰에서 내보낸 파일로 읽기 규칙을 시험하고, 읽지 못한 줄은 사용자에게 알림. 개발 빌드는 필요 없음 |
| 내 이름 고르기 | txt에서 읽은 말한 사람 중 사용자가 내 이름을 고름. 스토리보드 6번을 'txt: 내 이름 고르기 · 내 말 확인'으로 바꿔 반영함(2026.11.8 확정, 수정은 프론트엔드 담당) |
| 첫 지원 메신저 | 카카오톡부터. 내 말은 txt에서는 사용자가 고른 내 이름으로, 이미지에서는 오른쪽 · 노란색 말풍선으로 구분. 디스코드 등 다른 메신저는 로드맵 (2026.10.28 확정, 구분 방식은 2026.11.8 변경) |
| 원문 보관 안내와 삭제 규칙 | 글자를 가리지 않고 원문을 1년 보관하는 것에 대해 동의 화면 · 약관에 AI 전송과 보관 기간을 분명히 안내하고, 철회하면 30일 뒤, 탈퇴하면 바로 원문을 지워요(2026.11.8 확정) |
| 하루 단위 대화의 메신저 요약 | 2026.10.28 결정: 그날의 일기 + 그날이 속한 주의 메신저 말투 분석(`traits`)만 사용(그 주의 일 · 대표 문장은 쓰지 않음). 말투 재현 목표(세부 목표 5)를 위한 것이라 팀원과 확인 |
| 커플 모드 개념 · 동의 문구 | 2026.11.7 확정: 서로 상대방의 과거 페르소나와 대화하고, 함께 볼 날 고르기 · 두 시점 비교도 같이 써요. 6.2 안내 문구는 이 흐름과 맞아서 그대로 써요 |
| 알림 구현 | "일기 작성 알림 받기"(선택 동의)를 실제로 보내는 방식과 기기 토큰 보관 방법 정하기 |
| 업로드 목표 수치 | 세부 목표 2의 "내 말 구분" 정확도 기준을 txt는 내 이름의 줄만 남는 비율 100%, 이미지는 카카오톡 스크린샷 12장 기준 90% 이상으로 정함(2026.11.8) |
