# Dear Us 서버 배포 (Render)

> 2026.11.18에 배포 준비를 마쳤어요. 서버 이미지는 `server/Dockerfile`, Render 설정은 레포 맨 위 `render.yaml`(Blueprint)이에요. 이 문서는 서비스를 처음 만드는 순서와 운영할 때 알아 둘 점을 모았어요.

## 정한 것 (2026.11.18)

| 항목 | 정한 내용 |
|---|---|
| 지역 | 싱가포르(`singapore`). Render에는 서울이 없고 서울 DB와 가장 가까워요. 서비스를 만든 뒤에는 바꿀 수 없어요 |
| 요금제 | 무료로 시작해요. 실제 사용자를 받기 전이나 발표 전에 Starter(월 7달러)로 바꿀지 다시 정해요 |
| DB | 지금 쓰는 공용 Supabase DB(서울)를 그대로 써요. 배포할 때 Flyway가 남은 마이그레이션을 적용해요 |
| 암호화 키 | `ENCRYPTION_KEY`는 공용 DB에 이미 암호화된 데이터가 있어서 `server/.env`와 **같은 값**이어야 해요. 다른 곳에 따로 보관하지 않고 Render 환경변수에만 둬요 |
| 가짜 로그인 | **배포 서버에서는 꺼요**(`DEV_LOGIN_ENABLED=false`, 2026.11.21). 레포가 공개라 서비스 주소와 앱의 고정 시험 토큰이 드러나 있어서, 켜 두면 누구나 시험 계정에 들어가고 AI 비용을 쓸 수 있어요. 소셜 로그인이 붙기 전에는 각자 PC의 서버로 시험해요 |
| 새벽 삭제 작업 | 무료 요금제는 잠들어서 새벽 4시 작업을 건너뛸 수 있어요. 그래서 서버가 켜질 때마다 밀린 삭제를 한 번 돌려요(`JOBS_RUN_ON_STARTUP=true`, `common/StartupJobs`) |

## 처음 한 번: 서비스 만들기 (백엔드 담당이 Render 화면에서 해요)

비밀 값은 대화나 문서에 붙여 넣지 말고, Render 화면에 직접 넣어요.

1. Render에 로그인하고 GitHub의 `dearus26/dearus` 저장소에 접근을 허락해요.
2. **New → Blueprint**를 고르고 이 저장소를 골라요. `render.yaml`을 읽어 `dearus-server`(Docker, 싱가포르, 무료)를 만들어요.
3. 값을 넣으라는 칸(`sync: false`)을 채워요. `server/.env`와 같은 값이에요.
   - `DB_URL` · `DB_USERNAME` · `DB_PASSWORD`: Supabase **Session pooler** 값(직접 연결 주소는 IPv6 전용이라 Render에서 안 돼요)
   - `ENCRYPTION_KEY`: `server/.env`와 같은 값(다르면 기존 일기 · 메신저 원문 · 분석을 못 읽어요)
   - `ANTHROPIC_API_KEY`: 2026.11.18에는 개발에 쓰던 키를 그대로 넣었어요. 그래서 PC와 배포 서버의 사용량 · 비용이 한 키에 섞이고, 키를 바꾸면 Render와 `server/.env`를 함께 바꿔야 해요
   - `KAKAO_APP_ID` · `GOOGLE_CLIENT_IDS`: 아직 없으면 비워 둬요(그 로그인은 501)
   - `ADMIN_PASSWORD`: 관리자 페이지(`<주소>/admin`) 비밀번호예요. 16자 이상이고(짧으면 서버가 켜지지 않아요), 비워 두면 관리자 페이지가 꺼져요(2026.11.25). 이미 만든 서비스는 Environment에서 직접 더해요
   - `JWT_SECRET`은 Render가 자동으로 만들어요
4. **Apply**를 누르면 첫 배포가 시작돼요. 이미지 빌드에 몇 분 걸려요.
5. 배포가 끝나면 서비스 주소(`https://dearus-server-xxxx.onrender.com` 같은 모양)를 열어 `/actuator/health`가 `{"status":"UP"}`인지 봐요.
6. 주소를 프론트엔드 담당에게만 알려요. 앱의 `app/.env`에 `EXPO_PUBLIC_API_MODE=live`, `EXPO_PUBLIC_API_URL=<주소>`로 넣으면 PC IP 없이 폰에서 바로 붙어요.

## 그 뒤: 다시 배포하기

- `main`에 `server/` 아래 파일이 바뀌어 합쳐지면 자동으로 다시 배포해요(`autoDeploy`, `buildFilter`). 앱 · 문서만 바뀌면 그대로예요.
- 새 마이그레이션이 있으면 배포된 서버가 켜질 때 공용 DB에 적용해요. 공용 DB에 먼저 적용하지 않은 마이그레이션은 `main`에 합치기 전에 팀에 알려요.
- 환경변수를 바꾸면 Render가 서버를 다시 켜요.

## 운영할 때 알아 둘 점

- **잠들기:** 무료 요금제는 15분 동안 요청이 없으면 잠들어요. 다음 요청은 서버가 다시 켜질 때까지 기다려요(2026.11.21 실제로 재 보니 잠든 서버의 첫 응답까지 약 109초였어요). 발표 직전에는 `/actuator/health`를 한 번 열어 깨워 두거나 Starter로 바꿔요.
- **메모리:** 무료는 512MB예요. 힙을 절반(약 256MB)으로 묶었어요. 2026.11.18 로컬에서 같은 설정으로 켜고 요청을 90번 보냈을 때 프로세스 전체가 약 350MB였어요. 메모리 부족으로 꺼지면 Render 로그에 나와요.
- **뒤에서 하던 일:** 메신저 요약 · 대화 준비처럼 뒤에서 돌던 일은 서버가 잠들거나 다시 켜지면 끊겨요. 끊긴 일은 10분이 지나면 실패로 처리돼서 사용자가 다시 시도할 수 있어요. 일이 도는 동안에는 앱이 상태를 계속 물어서 서버가 잠들지 않아요.
- **새벽 삭제 작업:** 서버가 켜질 때마다 돌고, 깨어 있으면 새벽 4시 · 4시 30분에도 돌아요. 각자 PC에서는 켤 때 돌지 않아요(기본값 꺼짐).
- **관리자 페이지:** `https://dearus-server.onrender.com/admin`에서 `ADMIN_PASSWORD`로 들어가 답변 신고를 확인해요(2026.11.25). 신고된 AI 답과 바로 앞 사용자 말만 보이고, 누가 신고했는지는 안 보여요. 관리자 토큰은 그 탭에만 8시간 남아요. 비밀번호를 바꾸면 들어가 있던 관리자도 모두 나가져요. 비밀번호는 팀원 두 명만 알고, 대화나 문서에 적지 않아요.
- **비밀 값:** 이미지에는 비밀 값이 들어가지 않아요(`server/.dockerignore`가 `.env`를 막아요). Render 서비스를 지우거나 `ENCRYPTION_KEY`를 잘못 바꾸면 암호화한 데이터를 읽을 수 없게 되고 백업도 없어요.
