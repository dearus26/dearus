일기, 카톡 요약, 페르소나 분석(재사용 저장), 대화, 커플 접근 제어가 어떻게 연결되는지 한 장에 모았습니다. 카톡 원본을 담는 테이블이 없다는 점이 이 설계의 핵심입니다.

2핵심 규칙

분석 결과 재사용

persona_analyses의 유일 키는 (user_id, anchor_date, window_days)입니다. window_days는 14(전후 2주)입니다.

  • 바로가기(1 · 6 · 12개월 전)는 anchor_date를 그 주 월요일로 맞춥니다. 직접 고른 날짜는 그대로 씁니다.
  • source_digest = 해시(구간 내 일기의 id, updated_at + 겹치는 kakao_weekly_summaries의 id, created_at)
  • 키와 digest가 모두 같으면 재사용, 다르면 다시 분석해 같은 행을 덮어씁니다. 일기를 고치거나 지우면, 또는 그 기간 카톡을 올리면 digest가 달라집니다.

카톡 원본은 어디에도 없음

kakao_uploads에는 파일이나 본문을 담는 컬럼이 없습니다. 주 단위 요약(summary_enc, traits_enc, sample_enc)만 남습니다.

  • 요약은 마스킹한 본인 발화에서 만든 것이고, 상대 메시지는 저장하지 않습니다.
  • expires_at = 업로드일 + 1년. 배치가 지난 행을 지우고, 업로드 행을 지우면 요약도 함께 지워집니다.
  • sample_enc의 대표 문장도 마스킹된 것입니다.

커플 접근 규칙

상대의 persona_analyses를 볼 수 있는 조건은 다음 세 가지가 모두 참일 때입니다.

  • couples.status = 'CONNECTED'
  • couple_members 두 행 모두 consented_at이 채워져 있음
  • 두 행 모두 revoked_at이 비어 있음

한 사용자는 활성 커플을 하나만 가집니다. couple_members(user_id)에 WHERE revoked_at IS NULL 조건의 부분 유니크 인덱스를 둡니다.

철회 · 해제 시 해당 couple_id의 chat_sessions(와 메시지 · 리포트)를 지우고 접근을 끊습니다.

삭제와 보관

  • 회원 탈퇴 시 users 행을 지우면 모든 테이블이 ON DELETE CASCADE로 즉시 지워집니다.
  • 예외로 chat_sessions.analysis_id는 ON DELETE SET NULL입니다. 분석 행이 재분석으로 바뀌어도 대화 기록은 남기 위해서입니다.
  • 암호화는 애플리케이션 레벨(AES-GCM 가정)이고, 키는 Render 환경변수에 둡니다. *_enc 컬럼만 해당합니다.
  • 컬럼 이름과 테이블 이름은 snake_case이고 코드 식별자 규칙(dearus)을 따릅니다.

한 번에 보는 대화 흐름

  • 시점 선택 → persona_analyses 조회 (키 + digest 확인)
  • 없거나 다르면 → 일기(diaries) + 겹치는 주 요약 읽기 → Gemini 분석 → 같은 행에 저장
  • chat_sessions 생성 (analysis_id 연결) → chat_messages 누적
  • 대화 종료 → reports 한 행 (세션당 하나)

3가정한 부분

  • 일기는 하루 한 건 — diaries에 (user_id, diary_date) 유일 제약을 두었습니다. 하루에 여러 번 쓸 수 있다면 제약을 빼야 하고, 캘린더 작성 표시는 그대로 날짜 기준입니다.
  • 감정 태그는 여러 개 — 한 일기에 여러 태그를 붙일 수 있게 diary_emotions를 따로 뒀습니다. 태그는 마스터 테이블 없이 코드의 enum(JOY, SAD, TIRED 등)으로 관리합니다. 하나만 고르는 방식이면 diaries.emotion 컬럼으로 줄일 수 있습니다.
  • 일기 본문과 대화 내용의 암호화 — 기획서 7장은 요약 · 말투 특징만 암호화한다고 적었습니다. diaries.content와 chat_messages.content는 평문으로 두었습니다. 암호화하려면 컬럼을 *_enc로 바꿔야 합니다.
  • 커플 철회 시 본인 분석은 유지 — 철회하면 그 커플의 대화 · 리포트를 지우지만, 상대가 본 적이 있는 내 persona_analyses 행은 개인 모드에서도 쓰므로 남겨 둡니다. “관련 분석 데이터 파기”(기획서 6.3)를 더 넓게 해석한다면 규칙이 달라집니다.
  • 없는 것 — 위기 신호 감지 기록(기획서 5.6), 로그인 갱신 토큰 저장, 이용 시간 집계 전용 테이블은 넣지 않았습니다. 이용 시간은 chat_sessions의 시작 · 종료 시각으로 계산할 수 있습니다.
  • 커플 리포트 확장 — 기획서 9장의 “연인에게 물어보면 좋을 질문”은 아직 검토 중이라 reports에 컬럼을 두지 않았습니다.
